# NuoField Product Principles

## Product definition

A human–agent collaboration workspace that opens with a useful digital employee
team, treats agents as first-class citizens, keeps data and intelligent assets
under user sovereignty, and makes domestic models the native execution
ecosystem.

## Non-negotiable principles

### Agents are first-class citizens

An agent has its own identity, membership, permissions, resource limits,
task state, approved memory, audit trail, and lifecycle. It never impersonates
a human or inherits an unrestricted human credential.

### Data sovereignty belongs to users

A user may be an individual or an organization acting as the workspace tenant.
Users retain sovereignty over their content, identity, agent memory, skills,
knowledge, evaluations, indexes, model interactions, audit records, and other
derived intelligent assets.

An operator may hold infrastructure, storage, and keys on a user's behalf.
Infrastructure custody does not transfer ownership. Users must be able to see
and close model egress, export and migrate their assets, verify deletion, and
keep core workflows available without a hosted control plane.

### Domestic models are native

Domestic cloud APIs, local inference, and enterprise-private endpoints share
a replaceable routing layer. Routing can consider capability, sensitivity,
cost, and availability. Overseas services are optional and removable.

### A useful team is present from first boot

A completed deployment includes a default digital employee team called the
Fieldkeepers. It can guide setup, perform approved work, review evidence, and
care for the instance before the user creates any custom agent.

Users can change its skills, knowledge, permissions, memory, and models or add
new employees. Those changes are portable, versioned, reviewable, and
reversible. Model weight fine-tuning is optional, never an adoption
prerequisite.

## Supporting requirements

Mainland-ready supply chains, enterprise identity, approval workflows,
domestic notification channels, and Feishu/WeCom/DingTalk integrations support
the constitution. They are not substitutes for it.

## First product test

One user deploys a workspace, sees the default Fieldkeepers report their status,
and assigns one real task without first authoring an agent. The assigned agent
can access only approved data and tools, model egress is visible, risky actions
pause for approval, and the user can export the complete result, evidence, and
employee assets.

If this loop is not materially clearer than using an IM client, an AI chat
window, and a terminal separately, the product has not yet demonstrated value.
